> **Status: in progress.** This page lists what the `nanyx` executable does today. It is part of the
> [compilation](./compilation) workstream. [Files and projects](../getting-started/files-and-projects) is the
> user's guide to running code.

`nanyx` is a small C# CLI over the compiler pipeline (`Nanyx.Compiler.Cli`), implemented with Consolo. Its
entrypoint and help text are generated by Consolo from the command method in `Program.cs`.

# Usage

```
nanyx <run|check|parse> <file.nyx>
nanyx wasm <file.nyx> [--out <path>]
nanyx <run|check> [<directory or .nyxp>]
nanyx build [<directory or .nyxp>] [--out <path>]
nanyx new <name> [<directory>]
nanyx format [--check | --write] <files or directories>
nanyx lsp
nanyx hello
```

- `run` compiles the file and executes it on the embedded Wasmtime engine. The program's output is the
  only thing written to stdout; diagnostics go to stderr.
- `wasm` writes WebAssembly text next to the input (or to `--out`, making its directory if need be).
- `check` prints the compile phase and diagnostics, then the type of each top-level def the file declares, in
  source order, as hover writes it, with type variables `a`, `b`, ...: `greet : string -> string`, or
  `twice : [ToString(a)] a -> string` for a def that requires a context. It prints nothing from the prelude or
  the file's imports (`TypeHints.topLevelTypes`).
- `parse` prints the AST.
- `format` rewrites the files that are not formatted, or with `--check` lists them and exits with 1 (see
  [Formatter](./formatter)).
- `lsp` runs the language server over standard input and output (see
  [Language server and editor](./language-server)).

`run`, `build` and `wasm` are debug builds: they compile a program with type or name errors all the same, and
report each error if the program reaches it. `build --release` and `wasm --release` refuse them (see
[Deferred errors](./deferred-errors)).

`run --check-memory` checks the program's reference counting as it runs (`WasmOptions.CheckMemory`; see
[Memory management](./memory-management)). It stops with exit code 70 at a block freed twice or an object counted
after it was freed. When the program finishes with blocks it never freed, it fails with 1. The Wasm tests run every
program this way, so a leak anywhere fails a test.

Every command exits with the same codes (`UsageError` in `Program.cs`; `ExitCodeTests.fs`):

- **0** when it succeeds. A program that `run` runs exits with its own status instead.
- **1** when the code has errors, a package's manifest can't be read or found, or the program fails.
- **2** when the command is used wrongly: more than one path, a file or manifest that does not exist, or an
  option's value it doesn't take. `format` also exits with 2 for a file it could not format.

`nanyx hello` takes no file: it compiles and runs a "hello world" program built into the CLI, as a
quick check that the compiler and runtime work.

# The stopwatch

While `run`, `build`, `check` or `wasm` compiles, a stopwatch on stderr names the file the compiler is on and how
long the compile has taken, rewritten in place ten times a second: `Compiling src/main.nyx… 4.7s`. When the
compile finishes it is replaced by `Compiled greeter (12 files) in 4.7s`, or `Compiled main.nyx in 1.2s` for a
script, and the diagnostics follow. It is shown only when stderr is a terminal: a pipe, a log file and CI see
nothing, and the command's other output is the same either way (`CompileProgress.cs`). The compiler tells the
CLI which file it is on through `Package.buildWith`, which takes a callback that `Package.build` leaves out.

# Packages

Given a directory or a `.nyxp` manifest instead of a file, or nothing at all, `run`, `build` and `check`
work on a package: the manifest in that directory (the current one by default) or the nearest directory
above it.

- `build` checks every source file the manifest's `sources` select, with the linters its `[linters]`
  table turns on, and writes the program of the package's `@entry` to `out/<package name>.wat` beside the
  manifest (or to `--out`). A package without an `@entry` is only checked.
- `run` does the same checks, then runs the `@entry`.
- `check` does the same checks and writes nothing. Any error fails it, including one a debug build would defer.

`nanyx new acme.demo` makes a package in a new directory, `demo` (the name's last segment) unless another
is given: `acme.demo.nyxp`, with the official linter on, and `src/main.nyx`, whose `@entry` prints
"Hello, World!". The name must be one the manifest accepts, and the directory must be new or empty.

A package runs only the linters its manifest names (`[linters.default]` for the official one), and a file
run on its own only those its `::linters` directives name (`::linters.default`, or
`::linters.default.unusedBindings = "error"` to set a rule's severity too). Without either, no linter runs. See
`examples/greeter` for a working package, and `examples/directives.nyx` for a script with directives.
